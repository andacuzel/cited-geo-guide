API v1

Scan and generate from your own code

A JSON API for the Citehound scan. It scores one page of a domain out of 100 for AI readiness, lists the fixes, shows the state of ten AI crawlers, compares two sites, and writes llms.txt, robots.txt and JSON-LD. The score measures readiness, not whether any assistant names a brand.

Get a key

A free key, by email.

Free keys allow 10 requests an hour and 40 a day. The key is in the email and is shown once.

The key email is transactional and carries no marketing. We store a one-way hash of the key and of your address, plus the masked address. We keep your address itself only if you tick the box. Every key email has a link that revokes the key. See the privacy page.

Quick start

Send the key in a header.

Use Authorization: Bearer <key>, or X-Citehound-Key: <key>. Keep the key out of URLs and public code.

curl 
export CITEHOUND_KEY=chk_your_key_here
curl "https://getcitehound.com/v1/scan?domain=example.com" \
  -H "Authorization: Bearer $CITEHOUND_KEY"

The full description is a machine-readable OpenAPI 3.1 file: /openapi.yaml. The other ways to use Citehound that are available now are on the integrations page.

GET /v1/generate/llms-txt Generate an llms.txt

Builds an llms.txt from a name, a one-sentence description and up to 20 pages. Pure text generation: nothing is fetched. Pass each page as "page=<url>|<description>", repeated, or use POST with JSON. llms.txt is an optional convention with no demonstrated effect on Google.

Needs a key. Answers 200, 400, 401, 403, 429, 503.

Parameters of GET /v1/generate/llms-txt
ParameterRequiredWhat it is
nameYes
descriptionYes
pageNoRepeat for each page, as "<url>|<description>".

A POST to the same path takes the same fields as a JSON body.

curl 
curl -G https://getcitehound.com/v1/generate/llms-txt \
  -H "Authorization: Bearer $CITEHOUND_KEY" \
  --data-urlencode "name=Example Co" \
  --data-urlencode "description=Project software for small design studios." \
  --data-urlencode "page=https://example.com/pricing|Plans and prices"

Example response 
{
  "type": "llms.txt",
  "content": "# Example Co\n\n> Project software for small design studios.\n\n## Pages\n- [Plans and prices](https://example.com/pricing)"
}

GET /v1/generate/robots-txt Generate an AI-crawler robots.txt

Builds a robots.txt that explicitly allows or blocks named crawlers from the ten Citehound tracks, with an optional Sitemap line. Pure text generation: nothing is fetched. Names are comma-separated in the query; POST accepts JSON arrays.

Needs a key. Answers 200, 400, 401, 403, 429, 503.

Parameters of GET /v1/generate/robots-txt
ParameterRequiredWhat it is
allowNoComma-separated crawler names to allow.
blockNoComma-separated crawler names to block.
sitemapNo

A POST to the same path takes the same fields as a JSON body.

curl 
curl -G https://getcitehound.com/v1/generate/robots-txt \
  -H "Authorization: Bearer $CITEHOUND_KEY" \
  --data-urlencode "allow=GPTBot,ClaudeBot" \
  --data-urlencode "block=Bytespider"

Example response 
{
  "type": "robots.txt",
  "content": "User-agent: GPTBot\nAllow: /\n\nUser-agent: Bytespider\nDisallow: /\n\nSitemap: https://example.com/sitemap.xml",
  "allow": [
    "GPTBot"
  ],
  "block": [
    "Bytespider"

  "sitemap": "https://example.com/sitemap.xml"

GET /v1/events Pro: What changed, newest first

Events from the differences between two scans of the watched domains: score_dropped, score_improved, crawler_blocked, crawler_unblocked, llms_txt_added, llms_txt_removed, check_failed, check_fixed, scan_failed. Ids are stable and sort in time order, so a polling client can pass the newest id it has as "since" and take only what is new. To read further back, pass "next_cursor" as "cursor". "score_dropped" and "score_improved" fire at a change of 5 points or more. Events are kept 365 days.

Needs a key on Pro, Fix and Beyond (a lower plan gets 402 plan_required). Answers 200, 400, 401, 403, 404, 429, 503, 402.

Registers an https address that receives the events you choose as signed JSON (see "Webhooks" below for the headers and how to verify them). Up to 3 per key. Command line

Use it from a terminal or a build.

The citehound command on npm has no dependencies and needs Node.js 18 or newer. Its package page is npmjs.com/package/citehound.

Terminal 
npx citehound scan yourdomain.com
npx citehound scan yourdomain.com --fail-under 70
npx citehound compare mysite.com theirsite.com
npx citehound generate robots-txt yourdomain.com > robots.txt

Without a key the command uses the public endpoint of the MCP server and gives the full output, with public limits. To use your key, put it in the environment: CITEHOUND_API_KEY=chk_...; it is sent only to Citehound and never printed. With a key the command uses this API and your plan's limits. Where the Free plan has less than the public output (the full scan detail, compare, the full generated files, the other schema types), the command prints the full public result and the plan's message, so a key never gives you less. Pro, Fix and Beyond keys have higher limits and the full API output, as the plan table above shows. --fail-under exits with code 1 when a score is below the number you give.

Monitoring (Pro, Fix and Beyond)

Watch domains, get told when something changes.

Needs a key on Pro, Fix or Beyond. A free key gets 402 plan_required on these endpoints.

Add a domain with POST /v1/watchlist. It is scanned at once, and that scan is the baseline. A scheduled job runs once a day and re-scans the domains that are due, about 7 days after their last scan, oldest first. Each scan is compared with the one before and the differences become events. A scan that fails is tried again the next day, up to three times. A domain is scanned once for everyone who watches it.

Webhooks

A webhook receives each event you chose as a JSON POST. The address must be https on the default port and a public host; no redirect is followed. Each request carries X-Citehound-Timestamp (unix seconds), X-Citehound-Signature (v1= and the hex HMAC-SHA-256 of the timestamp, a dot and the raw body, keyed with your secret), X-Citehound-Event, X-Citehound-Event-Id and X-Citehound-Delivery. Any 2xx answer is a success. Otherwise it is retried after 1 minute, 10 minutes and 1 hour, at the next run of the scheduled job, so a retry can be up to a day late. After 5 deliveries in a row fail all their attempts, the webhook is disabled; delete it and create it again to start over. Use POST /v1/webhooks/{id}/test to send a test event and GET /v1/webhooks/{id}/deliveries to see the log.

Verify a delivery (Node.js) 
const crypto = require('crypto');

// rawBody: the request body exactly as received (a string, not parsed JSON).
// headers: the lower-cased request headers. secret: the secret of the webhook.
function verify(secret, headers, rawBody) {
  const ts = headers['x-citehound-timestamp'];
  const want = Buffer.from('v1=' + crypto.createHmac('sha256', secret).update(ts + '.' + rawBody).digest('hex'));
  const got = Buffer.from(String(headers['x-citehound-signature'] || ''));
  if (want.length !== got.length || !crypto.timingSafeEqual(want, got)) return false;
  return Math.abs(Date.now() / 1000 - Number(ts)) < 300;   // reject old deliveries
}

Scope

What it does not do.

The API measures readiness: whether crawlers can reach a site and whether its homepage carries signals a model can read. It does not measure whether any assistant names a brand, and the benchmark is our own archive of scans, dated as shown. It is read-only: it changes nothing on a scanned site. Browser calls from other sites are not allowed (no cross-origin access), so call it from a server.

Questions

Before you build.

What does the score mean?

It is a readiness score out of 100: whether AI crawlers can reach the site and whether its homepage carries signals a model can read. It does not measure whether any assistant names a brand. The same score appears in the web scan and the MCP server.

What does a scan read?

The public robots.txt, llms.txt, sitemap declaration and homepage of the domain you name, through the same guarded fetch as the web scan. One page, not the whole site. The API never sends your key, your address or any credential to the scanned site.

What do you keep about a key?

A one-way hash of the key, a one-way hash of your address, the masked address shown by /v1/me, the plan and the dates. Your address itself is kept only if you tick the update box. Counters for the limits expire within a day. The key email is transactional only.

Can I revoke a key?

Yes. Every key email has a link that revokes that key with one click. A revoked key answers 403 from then on.

Is there a paid plan?

Yes: Pro, Fix and Beyond keys have higher limits, and add the full scan detail, compare, full generated files, monitoring (a watchlist, scheduled re-scans, events, alert emails and webhooks), the fix list and the export, as the table above shows. A key gets its plan from us, and there is no checkout inside the API yet. Write to hey@getcitehound.com to ask.

What does monitoring keep?

For a Pro key: the domains it watches, a snapshot of each scan and the events between scans for 365 days, the address for alerts if you give one, and the addresses of your webhooks (their secrets are stored encrypted and never shown again). Revoking the key deletes all of it.
